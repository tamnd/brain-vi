##Giải pháp 

**Trả lời:**`260511850222`Cho phép$$F(a,b)$$biểu thị chi phí tối thiểu trong trường hợp xấu nhất cần thiết để xác định một số ẩn trong khoảng$[a,b]$. 

Nếu lần đầu tiên chúng ta hỏi$x$($a\le x\le b$), thì: 

- nếu số ẩn thấp hơn thì ta vẫn phải giải$[a,x-1]$, 
- nếu cao hơn thì phải giải$[x+1,b]$, 
- và trong cả hai trường hợp, chúng tôi đã thanh toán chi phí$x$. 

Vì thế$$F(a,b) = \min_{x\in[a,b]} \left( x+\max(F(a,x-1),F(x+1,b)) \right).$$Chức năng mong muốn là$$C(n)=F(1,n).$$Đối với các giá trị nhỏ:$$C(1)=0,\quad C(2)=1,\quad C(3)=2,\quad C(8)=12.$$Chương trình động trực tiếp quá chậm để$n=200000$, bởi vì nó sẽ yêu cầu$O(n^3)$làm việc trong tất cả các khoảng thời gian.

# Hiểu biết sâu sắc về cấu trúc chính 

Để chơi tối ưu, câu hỏi đầu tiên luôn ở rất gần đầu trên của khoảng thời gian. 

Nếu lần đoán đầu tiên là$k$, thì nhánh phải$[k+1,n]$được xử lý bởi cây quyết định nhị phân gần như hoàn chỉnh. 

Những chi phí “cây hoàn chỉnh” đó có thể được biểu diễn dưới dạng affine$$m\cdot a + c$$trong khoảng thời gian bắt đầu từ$a$. 

Điều này cho phép đánh giá chi phí bên phải một cách$O(1)$. 

Theo kinh nghiệm (và có thể chứng minh được), khoảng cách tối ưu$$d(n)=n-k(n)$$chỉ thay đổi gần lũy thừa của 2, do đó chỉ phải kiểm tra một tập hợp nhỏ các trục ứng cử viên cho mỗi$n$. 

Điều này làm giảm việc tính toán về cơ bản là thời gian tuyến tính.

#Triển khai Python```python
from bisect import bisect_left
from functools import lru_cache

# Numbers of the form 2^t - 1
G = []
x = 1
while x < 400000:
    G.append(x)
    x = x * 2 + 1

@lru_cache(None)
def complete_coeff(L):
    """
    Return (m, c) such that the complete-tree strategy
    on an interval [a, a+L] has worst-case cost:

        m*a + c
    """

    if L <= 0:
        return (0, 0)

    if L == 1:
        return (1, 0)

    if L == 2:
        return (1, 1)

    idx = bisect_left(G, L)
    t = G[idx - 1]

    # Pivot offset
    d = min(t, L - (t - 1) // 2)

    left_len = d - 1
    right_len = L - d - 1

    m1, c1 = complete_coeff(left_len)
    m2, c2 = complete_coeff(right_len)

    right_const = c2 + m2 * (d + 1)

    # Dominating branch
    if m1 > m2:
        md, cd = m1, c1
    elif m2 > m1:
        md, cd = m2, right_const
    else:
        if c1 >= right_const:
            md, cd = m1, c1
        else:
            md, cd = m2, right_const

    return (md + 1, d + cd)

def complete_cost(lo, hi):
    L = hi - lo
    m, c = complete_coeff(L)
    return m * lo + c

def solve(limit=200000):

    C = [0] * (limit + 1)

    # Small exact values
    seed = {
        1: 0,
        2: 1,
        3: 2,
        4: 4,
        5: 6,
        6: 8
    }

    for n, v in seed.items():
        if n <= limit:
            C[n] = v

    if limit <= 6:
        return sum(C[1:limit + 1])

    # Current optimal distance n-k
    dist = 3

    # Candidate perturbations
    q = [0]
    p = 4
    while p <= 131072:
        q.append(p)
        p *= 2

    i = 2

    total_sum = sum(C[1:7])

    for n in range(7, limit + 1):

        if dist > 4 ** i:
            i += 1

        best_cost = None
        best_dist = None

        for delta in q[:i]:

            k = n - dist - delta

            if not (0 < k < n):
                continue

            left = C[k - 1]
            right = complete_cost(k + 1, n)

            worst = max(left, right)

            cost = k + worst

            if best_cost is None or cost < best_cost:
                best_cost = cost
                best_dist = dist + delta

        C[n] = best_cost
        dist = best_dist

        total_sum += best_cost

    return total_sum

print(solve(100))      # 17575
print(solve(200000))

### DP chính 

Đối với mỗi$n$: 

- chỉ thử một tập hợp rất nhỏ các trục ứng cử viên, 
- tính toán$$k+\max(C(k-1),\text{right-cost})$$- lấy mức tối thiểu. 

Bởi vì trục quay tối ưu di chuyển chậm nên chỉ có nhiều ứng cử viên được thử nghiệm theo logarit.
